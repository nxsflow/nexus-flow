---
type: added
facade: breaking
---
[en]
A plugin can now declare a list field — `[fields.<name>] list = true` — for several values of one kind on an item, such as a person's e-mail addresses or phone numbers. Each entry is a value of the field's `type` (`text`, `date`, `datetime` or `enum`, validated as a single value is) with an optional free-text label such as `work` or `private`. Entries are added and removed with `nxf entry add <id> <field> <value> [--label <label>]`, `nxf entry remove <id> <field> <value>` and read with `nxf entry list <id> <field>`; over MCP with `flow_entry_add`, `flow_entry_remove` and `flow_entry_list`; on the facade with `Engine::field_entry_add`, `field_entry_remove` and `field_entries`. `update --set <field>=` (empty) clears a list; a non-empty `--set` on a list field is refused. Records return the entries under `custom` as `[{"value": ..., "label": ...}]` in the order their values were first added, and `nxf schema --json` / `flow_schema` mark the field `"list": true`. Entries merge as an observed-remove set across devices: the value is the entry's identity, the latest add of a value sets its label, and an add the remover had not seen survives a concurrent remove or clear. A list field cannot be `required`, a `longtext`, take a `merge`, or be read by a ranking key, and its name is at most 64 characters. `entry add` and `entry remove` report the entry as stored (a `datetime` entry in UTC); `entry remove` removes any entry on show, even one whose value the field's type or `on` scope no longer accepts. The task reducer's fold revision moves to 3, so replicas and hosted streams fold their log once more on upgrade; until a hosted stream is refolded its board reads answer `NotCurrent` (the hosted index revision stays 3), and a hosted board reads one more Query per item record. Breaking for embedders: `plugin::FieldDecl` gains the field `list` and `read::SchemaField` the field `list`, and both are now `#[non_exhaustive]`; `read::ActiveTicket` and `read::ListItem` gain `custom_lists` (additive, they were already non-exhaustive); `FieldEntry` is re-exported at the crate root. `Engine::field_entry_add` / `write::entry_add` return the stored `FieldEntry`, `Engine::field_entry_remove` / `write::entry_remove` the value as matched, and `write::entry_add_receipt` / `entry_remove_receipt` spell the receipts.
[de]
Ein Plugin kann jetzt ein Listenfeld deklarieren — `[fields.<name>] list = true` — für mehrere Werte einer Art an einem Item, etwa die E-Mail-Adressen oder Telefonnummern einer Person. Jeder Eintrag ist ein Wert des `type` des Felds (`text`, `date`, `datetime` oder `enum`, geprüft wie ein einzelner Wert) mit einer optionalen freien Kennzeichnung wie `work` oder `private`. Einträge werden mit `nxf entry add <id> <feld> <wert> [--label <kennzeichnung>]` und `nxf entry remove <id> <feld> <wert>` hinzugefügt und entfernt und mit `nxf entry list <id> <feld>` gelesen; über MCP mit `flow_entry_add`, `flow_entry_remove` und `flow_entry_list`; in der Fassade mit `Engine::field_entry_add`, `field_entry_remove` und `field_entries`. `update --set <feld>=` (leer) leert eine Liste; ein nicht leeres `--set` auf ein Listenfeld wird abgelehnt. Records geben die Einträge unter `custom` als `[{"value": ..., "label": ...}]` zurück, in der Reihenfolge, in der ihre Werte zuerst hinzugefügt wurden, und `nxf schema --json` / `flow_schema` markieren das Feld mit `"list": true`. Einträge mergen geräteübergreifend als Observed-Remove-Set: Der Wert ist die Identität des Eintrags, das letzte Hinzufügen eines Werts setzt seine Kennzeichnung, und ein Hinzufügen, das der Entfernende nicht gesehen hat, übersteht ein gleichzeitiges Entfernen oder Leeren. Ein Listenfeld kann weder `required` noch `longtext` sein, kein `merge` haben und von keinem Ranking-Schlüssel gelesen werden, und sein Name hat höchstens 64 Zeichen. `entry add` und `entry remove` melden den Eintrag so, wie er gespeichert ist (einen `datetime`-Eintrag in UTC); `entry remove` entfernt jeden sichtbaren Eintrag, auch einen, dessen Wert der Typ oder der `on`-Bereich des Felds nicht mehr annimmt. Die Fold-Revision des Task-Reducers steigt auf 3, Repliken und gehostete Streams falten ihr Log beim Update also einmal neu; bis ein gehosteter Stream neu gefaltet ist, antworten seine Brett-Lesezugriffe mit `NotCurrent` (die gehostete Index-Revision bleibt 3), und ein gehostetes Brett liest pro Item-Record eine Query mehr. Brechend für Einbettende: `plugin::FieldDecl` bekommt das Feld `list` und `read::SchemaField` das Feld `list`, beide sind jetzt `#[non_exhaustive]`; `read::ActiveTicket` und `read::ListItem` bekommen `custom_lists` (additiv, sie waren schon non-exhaustive); `FieldEntry` wird an der Crate-Wurzel re-exportiert. `Engine::field_entry_add` / `write::entry_add` geben den gespeicherten `FieldEntry` zurück, `Engine::field_entry_remove` / `write::entry_remove` den Wert, wie er getroffen wurde, und `write::entry_add_receipt` / `entry_remove_receipt` formulieren die Quittungen.
