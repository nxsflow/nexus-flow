[en]
A plugin can now declare a list field — `[fields.<name>] list = true` — for several values of one kind on an item, such as a person's e-mail addresses or phone numbers. Each entry is a value of the field's `type` (`text`, `date`, `datetime` or `enum`, validated as a single value is) with an optional free-text label such as `work` or `private`. Entries are added and removed with `nxf entry add <id> <field> <value> [--label <label>]`, `nxf entry remove <id> <field> <value>` and read with `nxf entry list <id> <field>`; over MCP with `flow_entry_add`, `flow_entry_remove` and `flow_entry_list`; on the facade with `Engine::field_entry_add`, `field_entry_remove` and `field_entries`. `update --set <field>=` (empty) clears a list; a non-empty `--set` on a list field is refused. Records return the entries under `custom` as `[{"value": ..., "label": ...}]` in the order their values were first added, and `nxf schema --json` / `flow_schema` mark the field `"list": true`. Entries merge as an observed-remove set across devices: the value is the entry's identity, the latest add of a value sets its label, and an add the remover had not seen survives a concurrent remove or clear. A list field cannot be `required`, a `longtext`, take a `merge`, or be read by a ranking key. The task reducer's fold revision moves to 3, so replicas and hosted streams fold their log once more on upgrade; a hosted board reads one more Query per item record. Breaking for embedders: `plugin::FieldDecl` gains the field `list` and `read::SchemaField` the field `list`, and both are now `#[non_exhaustive]`; `read::ActiveTicket` and `read::ListItem` gain `custom_lists` (additive, they were already non-exhaustive); `FieldEntry` is re-exported at the crate root.
[de]
Ein Plugin kann jetzt ein Listenfeld deklarieren — `[fields.<name>] list = true` — für mehrere Werte einer Art an einem Item, etwa die E-Mail-Adressen oder Telefonnummern einer Person. Jeder Eintrag ist ein Wert des `type` des Felds (`text`, `date`, `datetime` oder `enum`, geprüft wie ein einzelner Wert) mit einer optionalen freien Kennzeichnung wie `work` oder `private`. Einträge werden mit `nxf entry add <id> <feld> <wert> [--label <kennzeichnung>]` und `nxf entry remove <id> <feld> <wert>` hinzugefügt und entfernt und mit `nxf entry list <id> <feld>` gelesen; über MCP mit `flow_entry_add`, `flow_entry_remove` und `flow_entry_list`; in der Fassade mit `Engine::field_entry_add`, `field_entry_remove` und `field_entries`. `update --set <feld>=` (leer) leert eine Liste; ein nicht leeres `--set` auf ein Listenfeld wird abgelehnt. Records geben die Einträge unter `custom` als `[{"value": ..., "label": ...}]` zurück, in der Reihenfolge, in der ihre Werte zuerst hinzugefügt wurden, und `nxf schema --json` / `flow_schema` markieren das Feld mit `"list": true`. Einträge mergen geräteübergreifend als Observed-Remove-Set: Der Wert ist die Identität des Eintrags, das letzte Hinzufügen eines Werts setzt seine Kennzeichnung, und ein Hinzufügen, das der Entfernende nicht gesehen hat, übersteht ein gleichzeitiges Entfernen oder Leeren. Ein Listenfeld kann weder `required` noch `longtext` sein, kein `merge` haben und von keinem Ranking-Schlüssel gelesen werden. Die Fold-Revision des Task-Reducers steigt auf 3, Repliken und gehostete Streams falten ihr Log beim Update also einmal neu; ein gehostetes Brett liest pro Item-Record eine Query mehr. Brechend für Einbettende: `plugin::FieldDecl` bekommt das Feld `list` und `read::SchemaField` das Feld `list`, beide sind jetzt `#[non_exhaustive]`; `read::ActiveTicket` und `read::ListItem` bekommen `custom_lists` (additiv, sie waren schon non-exhaustive); `FieldEntry` wird an der Crate-Wurzel re-exportiert.
