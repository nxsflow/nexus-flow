[en]
A plugin can now rank a type by one of its own custom fields. In a per-type order (`[ranking.list.<type>]` or `[ranking.next.<type>]`), a field key may name a custom field declared on that type, of any type except a list field: `[ranking.list.note] order = [ { field = "occurred_on", dir = "desc", nulls = "last" } ]` lists notes newest first, the notes without a date last, with the id breaking ties. The value is compared as for any field key: as numbers when both values are whole numbers, otherwise as text, so a `datetime` field ranks in time order. `list --sort rank` and `next` rank this way on a replica and on a server alike, and the server needs no extra reads for it. A custom field that is not declared, not declared on the type, or a list field is refused when the plugin loads, as is a custom field in a default `order`.
[de]
Ein Plugin kann einen Typ jetzt nach einem seiner eigenen Felder ranken. In einer Reihenfolge pro Typ (`[ranking.list.<typ>]` oder `[ranking.next.<typ>]`) darf ein Feldschlüssel ein eigenes Feld nennen, das für diesen Typ deklariert ist, jeden Typs außer einem Listenfeld: `[ranking.list.note] order = [ { field = "occurred_on", dir = "desc", nulls = "last" } ]` listet Notizen mit der neuesten zuerst, die Notizen ohne Datum zuletzt, und bei Gleichstand entscheidet die Id. Der Wert wird wie bei jedem Feldschlüssel verglichen: als Zahlen, wenn beide Werte ganze Zahlen sind, sonst als Text, sodass ein `datetime`-Feld in zeitlicher Reihenfolge rankt. `list --sort rank` und `next` ranken so auf einem Replikat wie auf einem Server, und der Server braucht dafür keine zusätzlichen Lesezugriffe. Ein eigenes Feld, das nicht deklariert ist, nicht für den Typ deklariert ist oder ein Listenfeld ist, wird beim Laden des Plugins abgelehnt, ebenso ein eigenes Feld in einer Standard-`order`.
