type: added
facade: breaking

[en]
A plugin can now declare a custom field of type `datetime` (`[fields.<name>] type = "datetime"`) for a moment such as a meeting's start. A value must be an RFC 3339 timestamp with a time zone (`Z` or an offset such as `+02:00`); a plain date or a time without a zone is refused. The value is stored as the same moment in UTC at whole seconds: `--set occurred_on=2026-10-12T10:30:00+02:00` stores `2026-10-12T08:30:00Z`, and fractional seconds are dropped. Surrounding whitespace is trimmed, and a space in place of the `T` is accepted. Because every value has that one shape, `datetime` values sort in time order wherever a field is read, such as a ranking key's `of = { field = "..." }`, locally and on a hosted board alike. The offset that was typed is not kept. `nxf schema --json` and MCP `flow_schema` report the field with `"kind": "datetime"`; `create`/`update --set` and MCP `flow_create`/`flow_update` validate it. Breaking for embedders that match on `plugin::FieldType`: it gains the variant `Datetime` and is now `#[non_exhaustive]`, so a match needs a wildcard arm; later field types will then be additive.
[de]
Ein Plugin kann jetzt ein eigenes Feld vom Typ `datetime` deklarieren (`[fields.<name>] type = "datetime"`), für einen Zeitpunkt wie den Beginn eines Meetings. Ein Wert muss ein RFC-3339-Zeitstempel mit Zeitzone sein (`Z` oder ein Offset wie `+02:00`); ein reines Datum oder eine Uhrzeit ohne Zone wird abgelehnt. Gespeichert wird derselbe Zeitpunkt in UTC auf ganze Sekunden: `--set occurred_on=2026-10-12T10:30:00+02:00` speichert `2026-10-12T08:30:00Z`, Sekundenbruchteile entfallen. Umgebende Leerzeichen werden entfernt, und ein Leerzeichen anstelle des `T` wird angenommen. Weil jeder Wert diese eine Form hat, sortieren `datetime`-Werte überall zeitlich, wo ein Feld gelesen wird, etwa im `of = { field = "..." }` eines Ranking-Schlüssels, lokal wie auf einem gehosteten Brett. Der eingegebene Offset bleibt nicht erhalten. `nxf schema --json` und MCP `flow_schema` melden das Feld mit `"kind": "datetime"`; `create`/`update --set` und MCP `flow_create`/`flow_update` prüfen es. Brechend für Einbettende, die auf `plugin::FieldType` matchen: Es bekommt die Variante `Datetime` und ist jetzt `#[non_exhaustive]`, ein Match braucht also einen Wildcard-Arm; spätere Feldtypen sind dann additiv.
