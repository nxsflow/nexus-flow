[en]
Saving a memory no longer touches `NEXUS_MEMORY.md` in a repository with an `origin`, so it never dirties a checkout, not even while a job holds the tree. The file now reaches the repository through its own pull request: the background service publishes it at most once a day when something changed, and the new `nxm doc --publish` does the same on demand. Both build the commit without touching any checkout, and need `gh` plus push rights. A checkout's copy can therefore lag the store by a while; `nxm prime` and `nxm recall` read the store and win. `nxm doc --check` now fails only on a hand edit, or on a file that should be there and is not, and reports a copy that is merely behind as a note with exit 0. After this update, each such repository on your machine gets a first publish pull request. A failed publish never fails a memory write: it is retried hourly and its reason stands in `nxm doc --check` and `nxs sync daemon status`. A workspace with no `origin` keeps writing the file directly. If an older `nxm` left the file modified and uncommitted, `nxm doc --check` reports it as a hand edit until you run `git restore NEXUS_MEMORY.md`. For a host embedding `nexus-memory`: `Engine::doc_publish`, `doc_publish_with` and `doc_publish_record` are new, a write through the handle no longer writes the file where there is an `origin`, and the exhaustive enums `project_doc::Drift` and `project_doc::Skip` gain `Pending` and `PublishedSeparately`, so a `match` over them needs an arm.
[de]
Eine Erinnerung zu sichern berührt `NEXUS_MEMORY.md` in einem Repository mit `origin` nicht mehr und verschmutzt damit keinen Checkout, auch nicht, während ein Job den Baum hält. Die Datei kommt jetzt über einen eigenen Pull Request ins Repository: Der Hintergrunddienst veröffentlicht sie höchstens einmal am Tag, wenn sich etwas geändert hat, und das neue `nxm doc --publish` tut dasselbe auf Anforderung. Beide bauen den Commit, ohne einen Checkout zu berühren, und brauchen `gh` und Push-Rechte. Die Kopie eines Checkouts kann deshalb eine Weile hinter dem Speicher liegen; `nxm prime` und `nxm recall` lesen den Speicher und gehen vor. `nxm doc --check` schlägt jetzt nur noch bei einer Änderung von Hand oder bei einer fehlenden Datei fehl, die da sein sollte, und meldet eine Kopie, die nur hinterherhinkt, als Hinweis mit Exit-Code 0. Nach diesem Update bekommt jedes solche Repository auf Ihrem Rechner einen ersten Veröffentlichungs-Pull-Request. Eine fehlgeschlagene Veröffentlichung lässt nie das Sichern einer Erinnerung fehlschlagen: Sie wird stündlich wiederholt, und ihr Grund steht in `nxm doc --check` und `nxs sync daemon status`. Ein Arbeitsbereich ohne `origin` schreibt die Datei weiter direkt. Hat ein älteres `nxm` die Datei geändert und nicht committet hinterlassen, meldet `nxm doc --check` das als Änderung von Hand, bis Sie `git restore NEXUS_MEMORY.md` ausführen. Für einen Host, der `nexus-memory` einbettet: `Engine::doc_publish`, `doc_publish_with` und `doc_publish_record` sind neu, ein Schreibvorgang über das Handle schreibt die Datei nicht mehr, wo es einen `origin` gibt, und die erschöpfenden Enums `project_doc::Drift` und `project_doc::Skip` bekommen `Pending` und `PublishedSeparately`, sodass ein `match` darüber einen weiteren Zweig braucht.
