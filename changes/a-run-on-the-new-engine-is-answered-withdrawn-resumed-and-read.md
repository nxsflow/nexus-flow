[en]
A run on the new engine (a channel declaring `engine: v2`, still being built) can now be answered, resumed, withdrawn and read with the commands you already use. The session the run started for a step answers in that step's thread with `nxc reply`, with or without `--thread`; nobody else can. You answer the run's question on its root thread with `nxc reply --thread <root>`, and `--accept` overrules a verdict only at a ceiling. A reply never restarts a run that is on hold or parked: `nxc resume --thread <root>` does, and before the hold lifts it says not yet unless you add `--force`. `nxc withdraw --thread <root>` takes the run back. Only the person who commissioned the run can do these from the terminal; a session cannot. `nxc status` lists such a run once, in the shape a watcher already reads (`open`, `needs_decision`, `awaiting_human`, `working_copy`), with the run's own status beside it under `run`; the human form says who attends the run and how long each member has been quiet; and `nxc status --run <id>` prints the run's status whole. The threads of such a run are now readable with `nxc threads show`. For a host embedding `nexus-chat`: `StatusOperation` gains `run`, `StatusThread::working_copy` becomes `StatusWorkingCopy` (its `fingerprint` is an `Option`), `StatusOperation` and `StatusReport` no longer implement `Eq`, `ResumeReceipt` and `WithdrawReceipt` gain `run`, and `Engine::withdraw`, `Engine::resume_interrupted` and `Engine::status` answer for such a run as the CLI does. The JSON of every existing operation is unchanged.
[de]
Ein Lauf auf der neuen Engine (ein Kanal, der `engine: v2` deklariert, noch im Aufbau) lässt sich jetzt mit den gewohnten Befehlen beantworten, fortsetzen, zurückziehen und lesen. Die Sitzung, die der Lauf für einen Schritt gestartet hat, antwortet im Thread dieses Schritts mit `nxc reply`, mit oder ohne `--thread`; niemand sonst kann das. Die Frage des Laufs beantwortest du in seinem Wurzel-Thread mit `nxc reply --thread <wurzel>`, und `--accept` setzt sich nur an einer Obergrenze über ein Urteil hinweg. Eine Antwort startet einen angehaltenen oder geparkten Lauf nie neu: das tut `nxc resume --thread <wurzel>`, und bevor die Sperre endet, sagt es „noch nicht“, außer mit `--force`. `nxc withdraw --thread <wurzel>` zieht den Lauf zurück. Nur wer den Lauf beauftragt hat, kann das vom Terminal aus; eine Sitzung kann es nicht. `nxc status` führt einen solchen Lauf einmal auf, in der Form, die ein Beobachter schon liest (`open`, `needs_decision`, `awaiting_human`, `working_copy`), mit dem eigenen Status des Laufs daneben unter `run`; die lesbare Form sagt, wer den Lauf betreut und wie lange jedes Mitglied still ist; und `nxc status --run <id>` gibt den Status des Laufs vollständig aus. Die Threads eines solchen Laufs sind jetzt mit `nxc threads show` lesbar. Für einen Host, der `nexus-chat` einbettet: `StatusOperation` bekommt `run`, `StatusThread::working_copy` wird zu `StatusWorkingCopy` (sein `fingerprint` ist ein `Option`), `StatusOperation` und `StatusReport` implementieren `Eq` nicht mehr, `ResumeReceipt` und `WithdrawReceipt` bekommen `run`, und `Engine::withdraw`, `Engine::resume_interrupted` und `Engine::status` antworten für einen solchen Lauf wie die CLI. Das JSON jeder bestehenden Operation bleibt unverändert.
