[en]
A hosted board now answers `list` ranked by the plugin's `[ranking.list]`, derived ranking keys included, exactly as a local replica does. The facade names what to read for a query (`read::list_reads`, a new `ListReads`), a server reads it into a new `ListBoard` with `nxs_fold_ddb::records::list_board`, and `read::list_board_page` / `read::list_board_value` filter (type, container, label, status), rank and project it with the code `list` runs locally; `read::list_board` reads the same board from a store. The hosted list is not paged: `limit` cuts it with the total disclosed, and `paginate` or a token is refused, as for the hosted `next`. A list that is not ranked costs its page, not the stream: `ListReads::select` (a new `ListSelect`) lets the server keep and cut on the item rows before it reads any join (`read::list_select`, and `ListBoard::cut` with a new `ListCut` carries the total counted before the cut), and the server reads its point reads by `BatchGetItem`; a ranked list reads its types' whole `list` scope, which its rank is computed over. A hosted `next` whose keys read the rank `[ranking.list]` gives a type now ranks too instead of being refused: `RankingReads` gains `list_types` and `RankingGraph` gains `listed` (both `#[non_exhaustive]`, so additive). For a server's operators, the table contract changes: a third sparse index, GSI `typed` — partition key `nxf_typed` (string, `<stream>#<type>`), sort key `sk` (string), projection ALL — set by the fold on every live item row (closed and archived included, removed on delete). Add the index to the stack first, then deploy the read; a fold against a table without the index writes the attribute harmlessly. It ships in fold index revision 3 together with the self-describing adjacency entries, so one refold covers both. For an embedder of `nxs-fold-ddb`: the `Table` trait gains `get_many` (one `BatchGetItem` per 100 keys, unprocessed keys sent again), `RecordsError` gains `Refolding`, `Watermark` gains `refold_until`, `board::reindex` returns the items whose index attributes did not fit, and an item op is refused (`Folded::Refused`) when its row would pass 400 KB together with its index attributes, at one `GetItem` more per op, instead of silently dropping off an index.
[de]
Ein gehostetes Brett beantwortet `list` jetzt nach dem `[ranking.list]` des Plugins gerankt, abgeleitete Ranking-Schlüssel eingeschlossen, genau so wie ein lokales Replikat. Die Fassade nennt, was für eine Anfrage zu lesen ist (`read::list_reads`, ein neues `ListReads`), ein Server liest es mit `nxs_fold_ddb::records::list_board` in ein neues `ListBoard`, und `read::list_board_page` / `read::list_board_value` filtern (Typ, Container, Label, Status), ranken und projizieren es mit dem Code, den `list` lokal ausführt; `read::list_board` liest dasselbe Brett aus einem Speicher. Die gehostete Liste wird nicht geblättert: `limit` schneidet sie mit offengelegter Gesamtzahl, `paginate` oder ein Token wird abgelehnt, wie beim gehosteten `next`. Eine nicht gerankte Liste kostet ihre Seite, nicht den Stream: `ListReads::select` (ein neues `ListSelect`) lässt den Server anhand der Item-Zeilen behalten und schneiden, bevor er einen Join liest (`read::list_select`; `ListBoard::cut` mit einem neuen `ListCut` trägt die vor dem Schnitt gezählte Gesamtzahl), und der Server liest seine Punktzugriffe per `BatchGetItem`; eine gerankte Liste liest den ganzen `list`-Bereich ihrer Typen, über den ihr Rang berechnet wird. Ein gehostetes `next`, dessen Schlüssel den Rang lesen, den `[ranking.list]` einem Typ gibt, rankt jetzt ebenfalls, statt abgelehnt zu werden: `RankingReads` bekommt `list_types` und `RankingGraph` bekommt `listed` (beide `#[non_exhaustive]`, also additiv). Für den Betrieb eines Servers ändert sich der Tabellenvertrag: ein dritter dünn besetzter Index, GSI `typed` — Partitionsschlüssel `nxf_typed` (String, `<stream>#<type>`), Sortierschlüssel `sk` (String), Projektion ALL —, den der Fold an jeder lebenden Item-Zeile setzt (geschlossene und archivierte eingeschlossen, beim Löschen entfernt). Zuerst den Index in den Stack aufnehmen, dann das Lesen ausrollen; ein Fold gegen eine Tabelle ohne den Index schreibt das Attribut folgenlos. Er kommt mit der Fold-Index-Revision 3 zusammen mit den selbstbeschreibenden Adjazenzeinträgen, ein Neufalten deckt also beides ab. Für Einbettende von `nxs-fold-ddb`: Das Trait `Table` bekommt `get_many` (ein `BatchGetItem` je 100 Schlüssel, unverarbeitete Schlüssel werden erneut gesendet), `RecordsError` bekommt `Refolding`, `Watermark` bekommt `refold_until`, `board::reindex` gibt die Items zurück, deren Index-Attribute nicht passten, und eine Item-Op wird abgelehnt (`Folded::Refused`), wenn ihre Zeile zusammen mit ihren Index-Attributen 400 KB überschritte — zum Preis eines `GetItem` mehr je Op —, statt still aus einem Index zu fallen.
