[en]
A fresh replica now shows the same board as its source when the source's log holds ops written by an older version (by two processes with a stale clock) that share one `(lamport, site)` coordinate. That covers a new machine, `nxs sync bind`, a snapshot and a hosted replica. Until now it silently dropped the second op of each such pair, and the source kept both. On one real board, three archived items were not archived on any fresh replica. The replica now keeps every op of the pair and folds them in the order the source holds them, so it shows exactly what the source shows. Its `nxs doctor` reports these coordinates the way the source's does. `Store::apply` no longer reports such an op as not taken. It still refuses an op that claims one of the replica's own coordinates. Hosted folding on DynamoDB always kept both ops and is unchanged.

Updating does not repair a replica that already dropped ops: the stream will not deliver them again. A replica is affected if the source's `nxs doctor` shows the `coordinates: ⚠` line and the replica holds fewer ops than the source. After updating, set such a replica up again from the stream, as on a new machine: bind an empty workspace to the stream. Take a new snapshot from an updated replica too. A snapshot taken by an affected replica carries the incomplete board.
[de]
Eine frische Replik zeigt jetzt dasselbe Brett wie ihre Quelle, wenn das Log der Quelle von einer älteren Version geschriebene Ops enthält (von zwei Prozessen mit veralteter Uhr), die sich eine `(lamport, site)`-Koordinate teilen. Das gilt für einen neuen Rechner, `nxs sync bind`, einen Snapshot und eine gehostete Replik. Bisher verwarf sie still die zweite Op jedes solchen Paares, während die Quelle beide behielt. Auf einem echten Brett waren dadurch drei archivierte Items auf keiner frischen Replik archiviert. Die Replik behält jetzt jede Op des Paares und faltet sie in der Reihenfolge, in der die Quelle sie hält. So zeigt sie genau, was die Quelle zeigt. Ihr `nxs doctor` meldet diese Koordinaten so wie der der Quelle. `Store::apply` meldet eine solche Op nicht mehr als nicht übernommen. Eine Op, die eine Koordinate der eigenen Replik beansprucht, verweigert es weiterhin. Das gehostete Falten auf DynamoDB hat immer beide Ops behalten und bleibt unverändert.

Das Update repariert keine Replik, die bereits Ops verworfen hat: Der Stream liefert sie nicht noch einmal. Eine Replik ist betroffen, wenn `nxs doctor` auf der Quelle die Zeile `coordinates: ⚠` zeigt und die Replik weniger Ops hält als die Quelle. Richte eine solche Replik nach dem Update neu aus dem Stream ein, wie auf einem neuen Rechner: Binde einen leeren Workspace an den Stream. Nimm auch einen neuen Snapshot von einer aktualisierten Replik. Ein Snapshot, den eine betroffene Replik genommen hat, trägt das unvollständige Brett.
