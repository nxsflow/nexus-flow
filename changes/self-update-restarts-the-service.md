[en]
`nxs self-update` now restarts the background service when the service runs the binary that was just replaced. Before, the service kept running the old build until the next restart or reboot, so the fixes in an update were not active in the service, and nothing said so. A service that runs a different build, such as a development build, is not restarted; the existing note about it stays. If the restart fails, the update still succeeds, and the message gives you the command to run: `nxs sync daemon install`. With `--json`, a `service_restart` object reports `would-restart` (with `--check`), `restarted` or `failed`. `nxs sync daemon status` now tells you when the running service is an older version than the binary on disk.
[de]
`nxs self-update` startet den Hintergrunddienst jetzt neu, wenn der Dienst genau das Programm ausführt, das gerade ersetzt wurde. Bisher lief der Dienst bis zum nächsten Neustart des Dienstes oder des Rechners mit dem alten Build weiter. Die Korrekturen eines Updates waren im Dienst also nicht aktiv, und kein Hinweis machte darauf aufmerksam. Ein Dienst, der einen anderen Build ausführt, etwa einen Entwicklungs-Build, wird nicht neu gestartet; der bisherige Hinweis dazu bleibt. Schlägt der Neustart fehl, gilt das Update trotzdem als erfolgreich, und die Meldung nennt den Befehl, den du ausführen musst: `nxs sync daemon install`. Mit `--json` meldet ein Objekt `service_restart` den Zustand `would-restart` (mit `--check`), `restarted` oder `failed`. `nxs sync daemon status` sagt dir jetzt, wenn der laufende Dienst eine ältere Version ist als das Programm auf der Festplatte.
