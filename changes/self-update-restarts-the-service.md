[en]
`nxs self-update` now restarts the background service when the service runs the binary that was just replaced. Before, the service kept running the old build until the next restart or reboot, so the fixes in an update were not active in the service, and nothing said so. The restart keeps the `PATH` the service was installed with. A service that runs a different build, such as a development build, is not restarted; the existing note about it stays. Other instances that run the same binary are named, not restarted. If the update itself runs inside a process the background service started, the restart is skipped, because it would stop the update too. In that case, and whenever a restart fails, the update still succeeds. The message says what state the service was left in, including when it is stopped, and gives you the command to run: `nxs sync daemon install`. With `--json`, a `service_restart` object reports `would-restart` (with `--check`), `restarted`, `skipped` or `failed`. When `self-update` finds you already up to date, it tells you if the running service is still a different version of the binary. `nxs sync daemon status` now tells you that too. One limit: the restart writes the service definition from the version you are updating from. A change a new release makes to that definition takes effect at the next `nxs sync daemon install`.
[de]
`nxs self-update` startet den Hintergrunddienst jetzt neu, wenn der Dienst genau das Programm ausführt, das gerade ersetzt wurde. Bisher lief der Dienst bis zum nächsten Neustart des Dienstes oder des Rechners mit dem alten Build weiter. Die Korrekturen eines Updates waren im Dienst also nicht aktiv, und kein Hinweis machte darauf aufmerksam. Der Neustart behält den `PATH`, mit dem der Dienst installiert wurde. Ein Dienst, der einen anderen Build ausführt, etwa einen Entwicklungs-Build, wird nicht neu gestartet; der bisherige Hinweis dazu bleibt. Weitere Instanzen, die dasselbe Programm ausführen, werden genannt, aber nicht neu gestartet. Läuft das Update selbst in einem Prozess, den der Hintergrunddienst gestartet hat, wird der Neustart übersprungen, weil er das Update mit beenden würde. In diesem Fall und immer dann, wenn ein Neustart fehlschlägt, gilt das Update trotzdem als erfolgreich. Die Meldung sagt, in welchem Zustand der Dienst zurückbleibt, auch wenn er gestoppt ist, und nennt den Befehl, den du ausführen musst: `nxs sync daemon install`. Mit `--json` meldet ein Objekt `service_restart` den Zustand `would-restart` (mit `--check`), `restarted`, `skipped` oder `failed`. Stellt `self-update` fest, dass du schon auf dem neuesten Stand bist, sagt es dir, wenn der laufende Dienst noch eine andere Version des Programms ist. Das sagt dir jetzt auch `nxs sync daemon status`. Eine Grenze: Der Neustart schreibt die Dienstdefinition mit der Version, von der aus du aktualisierst. Ändert ein neues Release diese Definition, wirkt die Änderung erst beim nächsten `nxs sync daemon install`.
