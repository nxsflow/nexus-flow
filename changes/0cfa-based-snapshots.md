[en]
A snapshot can now carry a workspace's STATE without the ops it was folded from: `nxs sync snapshot <file> --based` writes format 2 — the board, the chat and the memory as they stand at the relay position the replica reached, and below that position only what the state cannot stand in for. `nxs sync bind --snapshot <file>` starts a fresh replica from it and pulls only the tail, so neither the file nor a replica that starts from it grows with the stream's history any more. That is what lifts the hosted cap on a long-lived stream: a hosted replica that counted every op of a stream's lifetime now counts only the tail since its last snapshot. Every build keeps reading format 1 (the whole log, which `nxs sync snapshot` still writes by default), and what a file is stands in its header; `--json` reports `format`, and for a based snapshot also `base` (its clock, the op count and digest below its position, the residue, the kept domains) and `revisions`. What rides along below the position: ops no reducer of this build could fold (an unknown shape, a Lamport number past the bound — the "residue", which folds once a later build understands it), and chat's whole log, because chat's actions read per-op provenance and a verdict is never taken from outside. A based snapshot is TAKEN or REFUSED, never folded again — there is no log to fold — so an import refuses by name and writes nothing when a product's views were folded by other rules than this build's (`NeedsRevision`), when it carries no views for a product this build folds (`MissingViews`), or when the relay does not hold the op it names at its position (`AnchorMismatch`); each refusal leaves the caller free to fall back to another snapshot or a full replay. Three things follow for a replica that started from one. Its Lamport clock travels in the snapshot, so its first write beats the state it imported instead of losing to it. Its database carries its own compatibility floor (substrate schema v9, which adds the `log_base` table), so an older nxs that cannot read that clock refuses the file rather than writing ops that lose silently — ordinary workspaces are unaffected and the global floor stays where it was. And rebuilding its views is refused by name (`NeedsHistory`) instead of emptying them: a rebuild re-derives the views from the whole log, which such a replica does not hold below its position, and the answer is a snapshot taken at this build's fold revisions. Proven against a generated 60,000-op stream with three writing sites and every op shape the three products fold: a replica started from a snapshot at half the stream plus the tail is identical to one that replayed all of it — every view table, every derived lane, every chunk — it never fetches an op below that position, and the result does not change when the tail arrives shuffled and doubled. Breaking for embedders: `nxs_foundation::store::Store::refold_if_behind` and `force_refold` now return `Result<(), nxs_foundation::image::NeedsHistory>`; `nxs_foundation::image::Image` gains `base`, and `ImageError` the variants `NeedsRevision`, `MissingViewBase` and `NeedsSchema`. Not yet in: publishing a snapshot to the relay, the signer trust list, and leaving a superseded chunk's body out of the file.
[de]
Ein Schnappschuss kann jetzt den ZUSTAND eines Arbeitsbereichs ohne die Ops tragen, aus denen er gefaltet wurde: `nxs sync snapshot <datei> --based` schreibt Format 2 — das Brett, den Chat und das Gedächtnis so, wie sie an der erreichten Relay-Position stehen, und unterhalb dieser Position nur das, was der Zustand nicht ersetzen kann. `nxs sync bind --snapshot <datei>` startet eine frische Replika daraus und holt nur noch den Rest, sodass weder die Datei noch eine daraus gestartete Replika weiter mit der Geschichte des Streams wächst. Genau das hebt die Obergrenze gehosteter Streams auf: Eine gehostete Replika, die jede Op der gesamten Lebenszeit zählte, zählt jetzt nur den Rest seit ihrem letzten Schnappschuss. Jeder Build liest Format 1 weiter (das ganze Log, das `nxs sync snapshot` standardmäßig weiterhin schreibt), und was eine Datei ist, steht in ihrem Kopf; `--json` meldet `format` und bei einem Based-Schnappschuss zusätzlich `base` (Uhr, Op-Zahl und Digest unterhalb der Position, Residuum, behaltene Domänen) sowie `revisions`. Was unterhalb der Position mitreist: Ops, die kein Reducer dieses Builds falten konnte (eine unbekannte Form, eine Lamport-Zahl über der Schranke — das „Residuum“, das faltet, sobald ein späterer Build die Form versteht), und das ganze Chat-Log, weil Chat-Handlungen die Herkunft je Op lesen und ein Urteil nie von außen übernommen wird. Ein Based-Schnappschuss wird ÜBERNOMMEN oder ABGELEHNT, nie neu gefaltet — es gibt kein Log dafür —, deshalb lehnt ein Import mit Namen ab und schreibt nichts, wenn die Sichten eines Produkts nach anderen Regeln als denen dieses Builds gefaltet wurden (`NeedsRevision`), wenn er für ein Produkt, das dieser Build faltet, keine Sichten trägt (`MissingViews`), oder wenn das Relay die Op nicht hält, die er an seiner Position nennt (`AnchorMismatch`); nach jeder Ablehnung bleibt dem Aufrufer der Rückfall auf einen anderen Schnappschuss oder ein vollständiges Nachspielen. Für eine so gestartete Replika folgt daraus dreierlei. Ihre Lamport-Uhr reist im Schnappschuss mit, ihr erster Schreibvorgang schlägt also den importierten Zustand, statt gegen ihn zu verlieren. Ihre Datenbank trägt ihre eigene Kompatibilitätsschwelle (Substrat-Schema v9, das die Tabelle `log_base` hinzufügt), damit ein älteres nxs, das diese Uhr nicht lesen kann, die Datei ablehnt, statt Ops zu schreiben, die still verlieren — gewöhnliche Arbeitsbereiche sind unberührt, und die globale Schwelle bleibt, wo sie war. Und ein Neuaufbau ihrer Sichten wird mit Namen abgelehnt (`NeedsHistory`), statt sie zu leeren: Ein Neuaufbau leitet die Sichten aus dem ganzen Log ab, das eine solche Replika unterhalb ihrer Position nicht hält, und die Antwort darauf ist ein Schnappschuss, der mit den Fold-Revisionen dieses Builds aufgenommen wurde. Belegt an einem erzeugten Stream mit 60.000 Ops, drei schreibenden Standorten und jeder Op-Form, die die drei Produkte falten: Eine Replika, die bei der Hälfte des Streams aus dem Schnappschuss startet und den Rest holt, ist von einer, die alles nachgespielt hat, nicht zu unterscheiden — jede Sichttabelle, jede abgeleitete Bahn, jeder Chunk —, sie holt nie eine Op unterhalb dieser Position, und das Ergebnis ändert sich nicht, wenn der Rest gemischt und doppelt ankommt. Brechend für Einbettende: `nxs_foundation::store::Store::refold_if_behind` und `force_refold` geben jetzt `Result<(), nxs_foundation::image::NeedsHistory>` zurück; `nxs_foundation::image::Image` bekommt `base` und `ImageError` die Varianten `NeedsRevision`, `MissingViewBase` und `NeedsSchema`. Noch nicht enthalten: das Veröffentlichen eines Schnappschusses auf dem Relay, die Vertrauensliste der Unterzeichner und das Auslassen des Rumpfs eines ersetzten Chunks.
