[en]
`nxf-relay purge <stream-id>` removes everything the relay holds for one stream — on SQLite, Postgres and DynamoDB. A `--dry-run` shows exactly what would go and prints a plan digest; `--yes --plan <digest>` deletes that plan and nothing else (exit 4 if the stream changed since the dry run); `--dry-run --expect-empty` confirms nothing is left. One JSON report on stdout, fixed exit codes, configuration from the environment only with no defaults, `--expect-identity` to pin the store, and stream ids only as log-id v1 tokens. `nxf-relay log-hash <kind> <id>` recomputes such a token under `NXS_LOG_HMAC_KEY`. The runbook is `docs/runbooks/relay-purge.md`.
The relay's SQLite connections now run with `secure_delete` on, so pages it frees no longer keep their old bytes (a file written by an older release still can: `VACUUM` it once with the relay stopped).
Every relay store now carries a store id (`relay_store_identity`, written once by the relay's own open), which the purge pins a store by. A store the current relay has never opened is refused by the purge until the relay has been started on it once.
[de]
`nxf-relay purge <stream-id>` entfernt alles, was der Relay zu einem Stream hält — auf SQLite, Postgres und DynamoDB. Ein `--dry-run` zeigt genau, was gelöscht würde, und gibt einen Plan-Digest aus; `--yes --plan <digest>` löscht genau diesen Plan und nichts sonst (Exit 4, wenn sich der Stream seit dem Dry-Run geändert hat); `--dry-run --expect-empty` bestätigt, dass nichts übrig ist. Ein JSON-Bericht auf stdout, feste Exit-Codes, Konfiguration nur aus der Umgebung und ohne Vorgaben, `--expect-identity` zum Festnageln des Speichers, Stream-IDs nur als log-id-v1-Token. `nxf-relay log-hash <kind> <id>` berechnet ein solches Token unter `NXS_LOG_HMAC_KEY` nach. Das Runbook ist `docs/runbooks/relay-purge.md`.
Die SQLite-Verbindungen des Relays laufen jetzt mit `secure_delete`, freigegebene Seiten behalten ihre alten Bytes nicht mehr (eine von einer älteren Version geschriebene Datei kann es noch: einmal bei gestopptem Relay `VACUUM` ausführen).
Jeder Relay-Speicher trägt jetzt eine Store-ID (`relay_store_identity`, einmal vom Relay beim Öffnen geschrieben), an der der Purge einen Speicher festmacht. Einen Speicher, den der aktuelle Relay nie geöffnet hat, lehnt der Purge ab, bis der Relay einmal darauf gestartet wurde.
