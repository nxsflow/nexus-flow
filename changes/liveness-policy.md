[en]
A workspace sets how many times a coordinated session found dead is resumed before its commissioner is escalated to: `[chat.liveness]` in `.nxs/config.toml`, with `dead_resumes` (1 to 3) and `notice_at_first_stop` (`true` or `false`; read and checked, the notice itself comes in a later version). Without the section the default is `dead_resumes = 1` and `notice_at_first_stop = false` — the behaviour so far. The file is read at every look, so an edit takes effect without a restart; `.nxs/` is not synced, so the setting is per machine. An invalid value or an unknown key never skips a look: the default for that key runs, the tick's receipt carries an `invalid_setting` warning naming the file, the key and the value, and an escalation says the default was used. Every tick receipt names the policy the look ran under (`liveness`).
`nexus-chat`: `Ctx` and `orchestration::Adapter` gain the required field `liveness: workspace::LivenessPolicy` (its `Default` is the default policy) — a host that builds either with a struct literal adds `liveness: Default::default()` or the policy it read. New: `workspace::{LivenessPolicy, ResolvedLiveness, liveness_policy}`, `Engine::liveness_policy` (the policy of the workspace the handle loaded, read once at open), `orchestration::liveness_findings`, `TickReceipt::liveness`, and `ConsequenceClass::InvalidSetting`.
[de]
Ein Workspace legt fest, wie oft eine koordinierte Sitzung, die tot vorgefunden wird, wieder aufgenommen wird, bevor an ihren Auftraggeber eskaliert wird: `[chat.liveness]` in `.nxs/config.toml`, mit `dead_resumes` (1 bis 3) und `notice_at_first_stop` (`true` oder `false`; gelesen und geprüft, der Hinweis selbst folgt in einer späteren Version). Ohne den Abschnitt gilt `dead_resumes = 1` und `notice_at_first_stop = false` — das bisherige Verhalten. Die Datei wird bei jedem Blick gelesen, eine Änderung wirkt also ohne Neustart; `.nxs/` wird nicht synchronisiert, die Einstellung gilt also je Rechner. Ein ungültiger Wert oder ein unbekannter Schlüssel lässt nie einen Blick aus: Es gilt der Standard für diesen Schlüssel, die Quittung des Ticks trägt eine Warnung `invalid_setting`, die Datei, Schlüssel und Wert nennt, und eine Eskalation sagt, dass der Standard galt. Jede Quittung eines Ticks nennt die Politik, unter der der Blick lief (`liveness`).
`nexus-chat`: `Ctx` und `orchestration::Adapter` erhalten das Pflichtfeld `liveness: workspace::LivenessPolicy` (sein `Default` ist die Standard-Politik) — ein Host, der eines davon als Struct-Literal baut, ergänzt `liveness: Default::default()` oder die Politik, die er gelesen hat. Neu: `workspace::{LivenessPolicy, ResolvedLiveness, liveness_policy}`, `Engine::liveness_policy` (die Politik des Workspaces, den das Handle geladen hat, einmal beim Öffnen gelesen), `orchestration::liveness_findings`, `TickReceipt::liveness` und `ConsequenceClass::InvalidSetting`.
