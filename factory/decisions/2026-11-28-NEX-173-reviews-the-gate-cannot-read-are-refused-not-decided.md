# 2026-11-28 · NEX-173 · Reviews the gate cannot read are refused, not decided

- Decided by: coder on NEX-173, confirmed by pm
- Why: RFC 0010 says what `--reviews` means when it is absent (the owner has not approved) and what a missing or malformed comments or verdict file means (no valid verdict, so `owner`), but not what a reviews file means that does not exist, is not a JSON array, or holds an entry without a `user` (an object with a string `login`, or `null`, which is no owner), a string `state`, and, for a deciding review, a `commit_id` (a string, or `null`, which is no commit) and a `submitted_at` in GitHub's `YYYY-MM-DDTHH:MM:SSZ`. Reading such a file as "no reviews" could hide an owner's request for changes and let a `pm` decision through; no code in RFC 0010's list of reasons names the case. It follows the reading NEX-172 gave an unreadable comments file: input the gate cannot read never counts in pm's favour. So `Engine::merge_gate_decide` refuses it with `Error::MergeGateInput`, and `nxs merge-gate decide` exits 1 with the error kind `validation`: the status check stays missing, which blocks the merge. A review in another state, such as `COMMENTED` or `PENDING`, is no deciding review and needs only `user` and `state`.
- Instead of: reading the file as no reviews, which can turn an owner's request for changes into a green check; a new reason code, which would widen the output contract the owner decides.
- Topics: merge-gate, reviews, output
