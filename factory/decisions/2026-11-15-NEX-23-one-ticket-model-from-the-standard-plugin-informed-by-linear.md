# 2026-11-15 · NEX-23 · One ticket model for every repository, from the standard plugin and what served us in Linear

- Decided by: Carsten
- Why: every repository we work in uses the standard `issue-tracker` plugin, so one model is generated from it for all; what served us in Linear is assessed first (NEX-24) and carried over. Team-specific types and fields are not designed now, and nexflow.it's plugin needs no place (NEX-18).
- Instead of: a generic field-value collection, a model per team, or a NoCentralDB plugin field type for team fields.
- Topics: nocentraldb, tickets, model, storage
