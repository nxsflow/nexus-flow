# 2026-11-15 · NEX-37 · Commits name the session role that made them

- Decided by: Carsten
- Why: the history then shows which role on which ticket did the work and who commissioned it, as NEX-16 does for NoCentralDB members. A commit's author name is the role on the ticket (`coder on NEX-123`, or `pm`), its author email the verified email of the agent account `nexusflow-ug` (`github@nxsflow.com`, CONFIG.md), never the owner's address. Every commit message carries a `Role:` trailer, because trailers survive the squash merge and author names do not; pm's squash message keeps the `Role:` and `Claude-Session:` trailers, and the owner stays `Co-authored-by`. The `commit-roles` workflow (`cargo xtask commit-roles`) fails a pull request against `v2` with a commit that lacks the trailer. It leaves out what no session can give the trailer: merge commits, commits already on the base branch, commits reachable from `origin/main` (v1 keeps shipping there, and main merges into v2 every week), and commits authored before the rule landed. The rule lands when the commit that adds `.github/workflows/commit-roles.yml` to `v2` is committed, which the check reads from git itself, so PRs opened before it (#142, #148, #150) need no rewrite and no date is hard-coded that could miss the merge day.
- Instead of: a fixed cutoff date for older commits, which would have to guess when the owner merges this; or the cloud session's default author (`Claude <noreply@anthropic.com>`), which names neither the role nor the ticket, or the owner's address, which puts personal data into a public history and makes the agent's work look like the owner's.
