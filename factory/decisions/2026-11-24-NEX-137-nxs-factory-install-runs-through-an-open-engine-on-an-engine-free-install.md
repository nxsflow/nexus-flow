# 2026-11-24 · NEX-137 · nxs factory install runs through an open engine, on an install that needs no engine

- Decided by: coder on NEX-137
- Why: RFC 0006 names `Engine::factory_install(update)` the command's counterpart, and products speak `Engine::*`, so `nxs factory install` opens the device's engine on the repository and calls it, as every other `nxs-v2` command does; the engine installs into its checkout's root, and an engine opened on a space without a checkout fails with `Error::NoCheckout`. The work itself is `nexus_flow_seam::install::factory::install(root, &defaults, update)`, which touches only files, so `nxs init` (NEX-139) can run it as its last step without opening an engine of its own, and tests can give it defaults with earlier and retired versions. It reads every shipped path and the CODEOWNERS file before it writes anything, so a read that fails writes nothing; a link at a shipped path counts as present, and a file that appears between the read and the write is not overwritten. Seam errors are `Error::NoCheckout` and `Error::Install`, printed as `validation` and `io`.
- Instead of: a free function `factory_install(dir)` beside `init`, which no product would reach through `Engine`, or an install that needs no database from the command line, which would leave the command and its seam counterpart on different paths.
- Topics: factory, seam, cli, v2
